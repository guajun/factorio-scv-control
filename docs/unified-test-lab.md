# 单存档测试大厅

一个 `SCV-Unified-Test-Lab.zip`，在左侧面板切换全部 56 个共享案例：11 个静态寻路、10 个真实闸门、5 个动态变化、30 个传送带案例。测试角色、场景、规划和执行代码来自现有 TestKit 模块；没有复制一份 GUI-only 寻路算法。

## 打开与操作

生成包位于 `F:\factorio-scv-testbench\unified\v1-<时间>\`。手动双击 `open-lab.cmd`，或在 PowerShell 中运行包内的 `open-save.ps1`。它会使用隔离的 mod 副本、配置和唯一存档打开游戏，不改正常 Factorio 的 mods 或 saves。自动测试从不执行这两个 GUI 入口。

进入后默认是暂停的 tight-clearance-corridor：

1. 在列表中选择案例，点击「载入案例」。静态案例可选择生产方案、栅格 A*、Dijkstra 或源多边形参考路线。
2. 「规划 / 预览」只生成路径；「运行」让真实角色执行到终态。状态面板分别显示终态和案例断言是否通过。
3. 「暂停 / 继续」控制游戏时钟。「重置案例」取消旧规划、移除旧角色并恢复所选场景。
4. 「自由右键（重置场景）」重置并将角色交给玩家。右键空地移动，Shift+右键排队，移动向下键（默认 S）停止。返回固定案例也会重置，避免复用手动修改后的起点或地图。

面板关闭后可用 `/scv-lab menu` 重新打开。命令还支持 `plan`、`run`、`pause`、`reset`、`free`、`watch`、`status`。自由移动的 planner/follower 日志写入包内 `script-output/scv-control/planner.jsonl` 和 `follower.jsonl`。

## 能力边界

- 生产方案现场规划。其余三项是从完整、通过的 44 行存档比较中提取的**固定起终点参考回放**，无需 Python 服务，不是假装实时运行外部 solver。原始 ZIP、事实、snapshot/query 身份保留；当前场景必须精确匹配原始事实，再通过当前共享 PlanningRun 和碰撞/轨迹验证。
- 自由右键只用当前生产 planner；算法下拉框不接管任意右键目标。闸门动作、动态变化响应和传送带补偿仍是固定领域实验，尚未整体部署到自由寻路。
- 部分「通过」代表预期的拒绝、失效停止、不可达，或历史对照中已知的传送带横漂，并非全部案例都安全到达。具体依据见各案例报告和领域执行设计。
- 大厅按需重建当前场景，并非把 56 张图拼成可步行大世界。它不取代 11 张静态与 45 张领域**不可变原始 ZIP**；正式 solver 比较仍重新加载那些原始地图、禁止重建几何。
- 场景地图为永久白天。重置会丢弃当前大厅场景中的手动编辑；需要保留观察结果时另存游戏，勿覆盖包内原始 ZIP。

## 生成与自动验证

```powershell
python .\tools\navigation\unified_lab.py --test
pwsh -NoProfile -File .\tools\test.ps1 -Suite unified
```

默认读取最近一份完整通过的存档比较报告，也可用 `--reference-report <comparison.json>` 指定。`--package <新目录>` 指定新包；若该目录已存在，则只读取并验证其归档，不覆盖。`--test` 会启动纯 headless 进程加载发布的同一 ZIP，检查全部 56 个案例可选、44 个静态配置运行、45 个领域运行，再检查原生角色生命周期、取消待处理规划和跨场景清理。成功须由实际终态及案例断言决定；超时仅为失败护栏。

包内 `manifest.json` 保存存档 SHA-256、mod 指纹与参考来源；`test-results.json` 关联该存档的实际验证。验证后存档必须保持原校验和。默认 `-Suite all` 同时保留原始存档评估与此大厅回归，不用便利大厅替换事实源评估。

Factorio 2.0.77 没有公开的 `game.create_player`。无玩家的 headless 新存档能执行全部原生案例，但无法据此声称已验证真实 GUI 布局或连接玩家的右键输入；报告的 `gui_coverage` 显式记录未覆盖。若测试存档含真实离线玩家，还能检查原生 GUI 控件及控制器切换；禁止对有连接玩家的服务运行这个破坏性生命周期测试。人工打开后的视觉与输入体验仍需检查。
